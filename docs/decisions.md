# Decisions

Where the project plan, the screens and the design system disagreed, this file says which one wins. Newest at the top. If you change a decision, edit it here first, then the code.

| # | Topic | Decision | Why | Overrides |
|---|---|---|---|---|
| D1 | Rendering | **3D: Three.js through React Three Fiber, drei and postprocessing.** Flowers are procedural meshes that turn to face the camera around their own vertical axis (Y-billboard), so they read like the 2D screens while living in real depth, fog and parallax. DOM interface floats over the canvas. | Chosen by the owner. The Y-billboard keeps the 2D botanical look of the screens and the design-system `Bloom` generator, so it can be ported rather than reinvented. | Design system's SVG `Bloom`/`Thread` (kept as the reference look, not used at runtime) |
| D2 | Forgetting numbers | **Design system v2:** S₀ = 7 garden days, tend multiplies S by 1.8, states vivid ≥ 0.6, fading ≥ 0.3, ghost ≥ 0.08, lost below. | Newer, and the components already use these thresholds. | Plan (S=10, ×1.5, 0.7/0.4/0.15) |
| D3 | Thread bonus | Each thread adds 5 × weight to S, **saturating at 8 days** (`THREAD_BONUS_CAP`). | `npm run sim` showed uncapped bonuses make a well-connected garden almost immortal (23 of 25 survived with no tending). With the cap, a neglected garden loses about half, and the survivors are the connected ones. | Plan ("each thread adds 5") |
| D4 | Is loss permanent? | **No. A lost memory leaves a small dark seed and keeps its words.** Returning costs 1 light and brings it back as a ghost (vitality 0.2, fresh stability). Its threads re-form. | The design system says "a lost memory can always be returned to", and so does the dissolve storyboard's last frame. Gentler loss fits pillar 1. | Plan's suggested answer ("text is gone") |
| D5 | Letting go | `let go` is the person's choice: the memory drifts to lost immediately, with no confirmation and no red. Same return rule as D4. | Design system Button rules. | — |
| D6 | Thread weight | Shared people + places: 1 → 0.85, 2 → 0.95, 3+ → 1.0. Feeling-only → 0.3. On screen, brightness = weight × min(1, √(vitalityA × vitalityB) / 0.9) (`threadBrightness`). | Reproduces the sample-content strengths (0.95, 0.85, 0.55, 0.45, faint) from rules, not hand-set numbers. | Plan's 3 integer levels (kept as `level`) |
| D7 | Tend spill-over | Each neighbour regains 30% × thread weight of what it has lost. | Plan's 30%, scaled by strength as the design system asks. | — |
| D8 | Light | 3 per real day, carry over up to 5, tend costs 1, return costs 1. | Plan. | — |
| D9 | Time | 1 real day = 1 garden week. After 14 real days away, fog runs at 25% speed (never stops). Hidden slider: press <kbd>`</kbd>. | Plan, plus its suggested answer for long absences. | — |
| D10 | Planting limit | Free during the first 7 plantings, then 3 per real day. | Plan's suggested answer. | — |
| D11 | Return line | Name memories, don't count them. "Four days passed. The library rooftop is about to be lost." rather than "3 memories faded." | The design-system Whisper forbids counts; screen 11 used them. Names make fading an invitation. | Screen 11 copy |
| D12 | Settings wording | Use "let the garden go" for delete-all, but the confirm step says plainly "This deletes every memory from this browser." | Voice rules forbid "delete", but privacy controls must be unambiguous. This is the one place plain words win. | Screen 13 copy, partly |
| D13 | Tagging | **Offline first.** The browser's offline tagger (compromise NLP + relation words + a feelings word list) tags every memory at planting. A provider is an optional upgrade, chosen by which key the server has: Claude `claude-haiku-5-5` (`effort: "low"`, structured output) if `ANTHROPIC_API_KEY` is set, else Groq `openai/gpt-oss-20b` (strict JSON schema, free tier) if `GROQ_API_KEY` is set, else 503. A provider's tags replace the offline ones when they arrive. The client stops asking after a 503, waits 3 minutes (or `retry-after`) after a 429, and gives up after 2.5s. | Lethe is a demo without a paid key. The garden must connect memories with no key at all, planting must never wait on the network, and a free tier must never be hammered. Haiku is plenty for a small extraction task. | Earlier D13 (Claude Opus only; offline matched known names only) |
| D14 | Hosting | Vercel: static Vite build plus one function, `/api/tag`. The dev server serves the same handler. | One deploy, same origin, no CORS, and the key stays server-side. | Plan offered Cloudflare or Vercel |
| D15 | Layout | Sample memories use the design-system layout (1440 × 900 canvas) mapped to world space. New memories are placed on a golden-angle spiral with ≥ 96px between bases. d3-force clustering is a stretch goal. | Deadline. The fixed layout already matches the screens. | Plan (d3-force) |
| D20 | Story mode: "watch a season" | The demo garden can play its own story in about 85 seconds: connection (hover Grandma Mei's sentence), choice (tend), a new memory finding its threads, two days away played as dusk, the library rooftop dissolving up close, the whole garden at dusk with what was held still glowing, the return, and the reveal. One caption at a time in the Whisper (sentence case, no counts), the first pillar said once, plainly: *"A garden that kept everything would have no shape. Forgetting is how it keeps what matters."* Entry: **watch a season** beside "see a garden" on the threshold, and beside "what holds you" in the demo garden only (never in your own garden). It reads "stop watching" while it plays; any click or key stops it and leaves a live garden. It only calls the store's existing actions (`src/ui/story.ts`). | A stranger has 3 minutes and the garden's rules take weeks to live. Shown, not told: every beat is a real moment of the product. improvement-ideas 2B asked that it stay invitational and skippable, so it is one word, opt-in, and any touch hands the garden back. | improvement-ideas 2B ("only if the video needs one take"); the P13 feature freeze, lifted by the owner for this |
| D19 | Threads in a big garden | Up to **60 threads, every thread is drawn**. Past that, the garden draws each flower's **2 strongest** threads, then the strongest of the rest up to 60. The threads of the hovered or open flower, and of the reveal's chosen person or place, are always drawn. The engine is untouched: an undrawn thread still holds its memories up. | `?stress=200` (a long-kept garden: a few people in many memories, a feeling on most) has 2,562 threads, 1,128 of them feeling-only. Each thread is three draw calls, which ran at under 2 fps on a laptop iGPU. At 160 the arcs still formed a wall of light over the whole garden; at 60 its clusters read (pillar 4). The demo garden has 8 threads, so it is unchanged. | scene-spec § Threads (every active thread drawn) |
| D18 | What a lost memory looks like | After the dissolve (storyboard p18), a lost memory is **a small dark seed with a faint ring on the ground, faint stems, and particles still drifting** where the flower stood (particles at 0.55, stems at half). Its fog bank thins to 0.05 so the seed stays legible. Clicking the seed opens the memory with "return". | The storyboard ends on "an empty spot, a small dark seed"; the design system and screen p16 show lost flowers as faint particle outlines. Both together: the seed says "it can be returned to", the particles say "it is drifting into fog". | Design system Bloom "lost" (outline only), storyboard frame 6 (seed only) |
| D17 | Where planting starts | "+ plant" sits at the **bottom-left**, where the design system puts PlantField. It opens the screens' overlay flow (p4 kind → p5/p6 field), floating low in the centre. <kbd>N</kbd> opens the field directly. | The design system reserves bottom centre for whispers; the screens put "+ plant" there. Both can't share it. | Screens p1/p14 ("+ plant" bottom centre) |
| D16 | Copy casing | Interface words are lowercase everywhere (`plant`, `tend`), including buttons the screens show capitalised. | Design system voice. | Screens 4–6 |
